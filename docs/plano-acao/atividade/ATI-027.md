# ATI-027 — Painel de telemetria sem backend de saída e sem pipeline

## O problema

`npm run telemetria` e `npm run dev` sobem o mesmo servidor, mas só o `dev` monta o pipeline de
movimento e o backend de saída. Quem abre o painel — que é justamente a ferramenta de quem está
medindo — **vê os eixos mexerem e o cursor não sair do lugar**, sem nenhuma explicação na tela.

Isso é pior do que um defeito comum, porque a pessoa conclui a coisa errada: "o pipeline está
quebrado". O painel é a testemunha do sistema; testemunha que engana é o pior tipo.

Além disso, o painel não mostra o bias em uso nem a recalibração acontecendo — dois números que
existem no servidor e que são exatamente o que se quer olhar durante uma sessão de ajuste.

## Escopo
- `npm run telemetria` monta pipeline e backend de saída pelas mesmas regras do `npm run dev`
  (mesma configuração, mesma chave de destino: dublê por padrão, real quando pedido).
- O painel mostra o **destino ativo** em destaque: `dublê (o cursor não vai se mexer)` ou
  `mouse real`. Quem estiver olhando precisa saber disso na primeira linha, sem procurar.
- O painel passa a mostrar: `bias` em uso por eixo, quando foi calibrado, se a recalibração
  automática está ligada e quantas vezes já ajustou na sessão.
- Enquanto o destino for dublê, mostrar o deslocamento **que teria acontecido** (pixels
  acumulados) — é o número que prova o pipeline funcionando sem tocar no cursor.
- Nada de duplicar a montagem: extrair o que hoje está em `principal.ts` para um módulo que os
  dois modos usam. Duas montagens que precisam concordar por coincidência é o mesmo vão de sempre.

## Critérios de aceite
- [ ] Com o painel aberto e o destino real, girar o aparelho move o cursor.
- [ ] Com o destino dublê, o painel diz isso claramente e mostra os pixels que teriam saído.
- [ ] `bias` em uso aparece no painel, e a recalibração automática se vê acontecendo.
- [ ] Nenhuma regra de montagem duplicada entre `dev` e `telemetria` (um módulo só, com teste).
- [ ] O painel continua sem piscar e sem rolagem, e a CPU segue abaixo de 5 %.
