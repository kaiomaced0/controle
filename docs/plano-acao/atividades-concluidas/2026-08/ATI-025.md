# ATI-025 — Cliente web de diagnóstico

## Objetivo
Permitir um teste **real** entre celular e PC hoje, com o giroscópio de verdade, sem depender
do build Android — que está impedido pela [ATI-024](../../atividade/ATI-024.md).

## Contexto
O firewall corporativo impede qualquer `gradlew` nesta máquina, então o app React Native não
pode ser compilado nem instalado. O restante do sistema (servidor, protocolo, transporte,
telemetria) está pronto e só falta um cliente que produza sensor de verdade.

O navegador do celular sabe ler giroscópio (`devicemotion`), vibrar (`navigator.vibrate`) e
falar WebSocket. Serve como cliente de diagnóstico e valida o servidor com dado real de um
aparelho real — o que nem o simulador nem o emulador entregam.

**Isto não substitui o app.** É instrumento de teste; o app continua sendo o produto.

## Escopo
- O servidor passa a servir uma página estática na mesma porta do WebSocket (8765), no
  caminho `/diagnostico`.
- A página, aberta no celular:
  - pede permissão de sensor quando a plataforma exigir (iOS pede explicitamente)
  - assina `devicemotion` e lê `rotationRate` (graus/s) convertendo para rad/s
  - usa `event.interval` como `dtMs`, com medição própria como reserva
  - faz o handshake `hello` e envia pacotes de MOVIMENTO (0x01) no formato do protocolo
  - mostra taxa medida, estado da conexão e os valores atuais
  - tem botões que enviam BOTAO (0x02) para testar clique
  - **vibra** ao receber RUMBLE (0x81) ou HAPTICO (0x82), fechando o ciclo de retorno
- Uso pelo cabo (recomendado): `adb reverse tcp:8765 tcp:8765` e abrir
  `http://localhost:8765/diagnostico` no navegador do celular — como é `localhost`, o
  navegador trata como contexto seguro e libera os sensores.
- Uso pelo Wi-Fi: documentar que os sensores exigem contexto seguro (HTTPS) e que, sem
  certificado, o caminho é o cabo.
- Reaproveitar o codec do servidor no navegador (mesmo formato, sem terceira cópia).

## Fora do escopo
Layout bonito, perfis, mapeamento de ações, movimento de cursor. É diagnóstico, não produto.

## Critérios de aceite
- [ ] Com o celular no cabo, a página conecta e a telemetria do PC mostra o giroscópio real.
- [ ] Girar o aparelho muda os números no PC de forma perceptivelmente instantânea.
- [ ] Taxa medida e RTT registrados com o aparelho do Kaio (modelo anotado no relatório).
- [ ] Botão da página aparece como pacote de BOTAO nos contadores do servidor.
- [ ] Comando de vibração enviado pelo PC faz o celular vibrar.
- [ ] Documentado no README do servidor, com o passo a passo do teste.

## Notas
Serve também como referência de comparação: quando o app Android voltar a compilar, dá para
comparar taxa e jitter do app nativo contra o navegador e provar o ganho do módulo nativo.
